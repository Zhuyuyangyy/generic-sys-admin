# 项目需求分析说明书

---

## 第一章 项目概述

### 1.1 项目背景

随着信息化建设的不断深入，各类政府机关、企事业单位对内部管理系统的需求日益多样化。传统管理系统的开发通常从零开始，存在以下痛点：

- **开发周期长**：每套系统都需要重新设计数据库、编写CRUD代码
- **代码复用性差**：相似功能在多个项目中重复开发
- **维护成本高**：技术栈不统一，维护人员需要熟悉多种框架
- **扩展能力弱**：新功能开发往往需要对原有代码进行大规模修改

本项目旨在设计并实现一套**高复用、易扩展的通用后台管理系统母版**，开发人员可在该母版基础上快速构建面向不同业务场景的管理系统，显著降低开发成本。

### 1.2 项目目标

本项目的核心目标包括：

1. **通用性**：一套系统母版适用于多种业务场景（用户管理、角色管理、内容管理、设备管理等）
2. **易扩展性**：新功能模块可通过配置化方式快速接入，无需大规模代码修改
3. **安全性**：基于JWT的无状态认证 + RBAC动态权限控制，保障系统安全
4. **可视化**：集成ECharts数据大屏和Three.js 3D可视化，提升用户体验
5. **智能化**：集成Minimax TTS语音播报，实现智能语音交互

### 1.3 项目范围

本系统的适用范围：

| 序号 | 适用场景 | 说明 |
|------|----------|------|
| 1 | 企业内部管理系统 | OA、CRM、HRM等 |
| 2 | 物联网设备管理平台 | 设备状态监控、远程控制 |
| 3 | 数据分析展示平台 | 运营数据大屏、报表系统 |
| 4 | 内容管理系统 | 文章发布、媒体管理 |
| 5 | 毕业设计/学科竞赛 | 作为项目开发母版 |

### 2.2 模块详细功能说明

#### 2.2.1 用户认证模块（auth）

**功能列表：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 用户登录 | 用户名+密码登录，返回JWT Token | P0 |
| Token刷新 | 携带refreshToken换取新Token | P1 |
| 登录日志 | 记录登录IP、时间、结果 | P1 |
| 密码修改 | 验证原密码后修改新密码 | P2 |

**业务流程：**
```
用户输入用户名/密码 → 后端验证 → 生成JWT Token → 返回前端 → 前端存储Token → 后续请求携带Token
```

**接口清单：**

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/auth/login` | POST | 用户登录 |
| `/api/auth/logout` | POST | 用户登出 |
| `/api/auth/refresh` | POST | 刷新Token |

#### 2.2.3 角色权限模块（role）

**功能列表：**

| 功能 | 说明 | 优先级 |
|------|------|--------|
| 角色列表 | 查询所有角色 | P0 |
| 角色新增 | 创建角色并分配菜单权限 | P0 |
| 角色编辑 | 修改角色信息 | P0 |
| 角色删除 | 删除角色（需校验是否有用户使用） | P0 |
| 权限配置 | 可视化配置角色的菜单访问权限 | P1 |
| 角色导出 | Excel导出角色数据 | P2 |

**RBAC权限模型说明：**

本系统采用RBAC（Role-Based Access Control）模型：

```
用户 ←N:M→ 用户角色关联表 ←N:M→ 角色
角色 ←N:M→ 角色菜单关联表 ←N:M→ 菜单

用户 → 角色列表 → 菜单权限列表 → 动态渲染菜单 + 按钮级别权限控制
```

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/role/page` | GET | 分页查询角色 |
| `/api/role/{id}` | GET | 查询单个角色 |
| `/api/role` | POST | 新增角色 |
| `/api/role` | PUT | 修改角色 |
| `/api/role/{id}` | DELETE | 删除角色 |
| `/api/role/{id}/menus` | PUT | 分配菜单权限 |

## 第三章 非功能需求

### 3.1 性能需求

| 指标 | 要求 | 说明 |
|------|------|------|
| 页面响应时间 | ≤2秒 | 列表页首次加载 |
| 接口响应时间 | ≤500ms | 单一接口（不含文件上传） |
| 文件上传 | ≤10秒 | 10MB以内文件 |
| 并发用户数 | ≥100 | 同时在线用户数 |
| 系统可用性 | ≥99.5% | 全年正常运行时间比例 |

### 3.2 安全性需求

| 需求项 | 说明 |
|--------|------|
| 身份认证 | JWT Token，2小时有效期 |
| 密码加密 | BCrypt加密存储 |
| SQL注入防护 | MyBatis-Plus参数化查询 |
| XSS防护 | 前端输入过滤 |
| CORS控制 | 仅允许配置来源的跨域请求 |
| 敏感操作日志 | AOP切面记录所有写操作 |

### 3.3 可扩展性需求

| 需求项 | 说明 |
|--------|------|
| 模块热插拔 | 新增模块仅需配置路由和菜单数据 |
| 存储策略可切换 | MinIO / 本地文件系统 / 未来云存储 |
| UI主题切换 | 亮色/暗色模式切换 |
| 国际化 | 中文/英文界面（预留） |

### 3.4 可靠性需求

| 需求项 | 说明 |
|--------|------|
| MinIO降级 | MinIO不可用时自动降级到本地存储 |
| TTS降级 | 无API Key时自动切换Mock模式 |
| 逻辑删除 | 所有删除操作均为逻辑删除，数据可恢复 |
| 启动检查 | 系统启动时自动检查MySQL、MinIO连通性 |

### 3.5 兼容性需求

| 需求项 | 说明 |
|--------|------|
| 浏览器支持 | Chrome/Firefox/Edge/Safari最新版 |
| 屏幕适配 | 1920×1080为主，1366×768兼容 |
| 移动端适配 | 表格横向滚动，菜单折叠 |

## 第六章 接口规范

### 6.1 统一响应格式

```json
{
  "code": 200,       // 业务状态码，200=成功
  "message": "操作成功",  // 提示信息
  "data": {}         // 返回数据（分页接口：{records:[], total:100, current:1, size:10}）
}
```

### 6.2 错误码规范

| 错误码 | 说明 |
|--------|------|
| 200 | 成功 |
| 400 | 请求参数错误 |
| 401 | 未认证 / Token失效 |
| 403 | 无权限访问 |
| 404 | 资源不存在 |
| 500 | 服务器内部错误 |

### 6.3 认证方式

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiJ9...
```

所有需要认证的接口（除登录外）均需在请求头中携带有效JWT Token。
